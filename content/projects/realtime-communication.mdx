## One real-time event model

Messages, delivery and read receipts, presence and typing indicators all travel as typed events over a single Socket.IO connection per client. One channel to scale, authorise and debug instead of several ad-hoc ones.

## From peer-to-peer calls to an SFU

Calling started as peer-to-peer WebRTC with public STUN servers. That works for one-to-one calls, but in a mesh every participant sends a stream to every other participant, so group calls get heavier as they grow. Moving calls to a **LiveKit SFU** (selective forwarding unit) means each client sends one stream and the server forwards it - group calls stay smooth on ordinary laptops.
