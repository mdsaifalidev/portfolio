## Messaging with RabbitMQ

Services communicate asynchronously over RabbitMQ using two patterns:

- **Events** - a service publishes that something happened and any interested service reacts, without the publisher knowing who is listening.
- **RPC** - request/reply over queues for cases where a caller needs an answer, without a direct HTTP dependency between services.

This decoupled the core business logic: services can be deployed, scaled and fail independently.

## AWS infrastructure

- Applications deployed on **EC2**.
- Images, PDFs, videos and backups stored in **S3**.
- **IAM** users, roles and permissions managed for least-privilege access.
- Domains connected with **Route 53**.
- Applications and servers monitored with **CloudWatch** logs.

## CI/CD and testing

I built **GitHub Actions** pipelines that run **Mocha/Chai** unit and integration suites on every change before building and shipping images. Automating the release path cut manual release effort by **~60%**, and growing the suites raised test coverage to **80%+**.
